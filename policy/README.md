# Policy artifacts

The scoring policy is proprietary and is **not** in this repository.

The engine contains no coefficients. Every weight, threshold and cutoff is
supplied by a versioned policy artifact loaded at runtime. If no artifact is
supplied the system fails at startup rather than falling back to built-in
values — a fallback would let a misconfigured deployment produce normal-looking
output from values that are not the policy, with nothing to indicate it.

## Files

| File | Committed | Purpose |
|---|---|---|
| `schema.json` | yes | The artifact schema. Key names are public; values are not. |
| `demo.v1.json` | yes | Demonstration pack, generated by `tools/make_demo_policy.py`. |
| `BOUNDARY_DEBT.txt` | yes | Outstanding engine/policy violations, ratcheted downward. |
| anything else | **no** | Blocked by `.gitignore` and by `tools/check_policy_boundary.py`. |

## Loading

```bash
export PEPTIDE_SUITE_POLICY=policy/demo.v1.json
```

```python
from peptide_suite.policy import load_policy
policy = load_policy()          # reads PEPTIDE_SUITE_POLICY
print(policy.banner())
```

Validation is strict in three directions: unknown keys are rejected, values
outside their declared range are rejected, and missing required fields are
rejected. The artifact also carries a SHA-256 digest computed over the document
with the integrity block removed, so modification after signing is detectable.

## Boundary enforcement

`tools/check_policy_boundary.py` runs as a pre-commit hook (`--scope staged`)
and in CI (`--scope all`). It blocks three things:

1. Any policy artifact that is not the demonstration pack. Absolute, always.
2. A coefficient hardcoded or defaulted in engine code.
3. Prose that justifies a weighting choice biochemically.

Classes 2 and 3 are ratcheted against `BOUNDARY_DEBT.txt` rather than allowlisted.
The recorded counts are violations from code written before the boundary
existed; the check fails if a count rises, so the retrofit can only move one
way. Lower the numbers as modules migrate to the policy artifact. Never raise
them.

To re-baseline after a deliberate reduction:

```bash
python tools/check_policy_boundary.py --scope all --write-debt
```


## Aggregate-term identifiers

Feature-family and threshold key names are public: they are the engine's
statement of what a pack must supply, and the engine is the part that gets
described in a paper. Aggregate terms are the exception. A key named
`interface.dispersion_fraction` in a shipped artifact tells a reader which
physics the policy found worth combining, and that is the finding itself,
separate from the number attached to it.

Aggregate terms are therefore declared as `agg.<12 hex>`, derived by
HMAC-SHA256 of the label under a private salt:

```python
from peptide_suite.policy import mint_term_id, load_salt
term_id = mint_term_id("some internal label", load_salt())
```

HMAC rather than a plain hash because the space of plausible chemistry phrases
is small enough to enumerate — a bare SHA-256 of a term name is recoverable by
running a wordlist through the same hash. The salt is the whole defence, so
`load_salt()` reads `PEPTIDE_SUITE_TERM_SALT` and raises when it is unset
rather than falling back to a built-in default. A default salt ships in the
source, which makes it a public salt, which makes the identifiers reversible.

The mapping from identifier back to label (`TermLegend`) is never committed and
`.gitignore` blocks it by name pattern. A debug surface without the legend
displays the raw identifier rather than failing, so nothing pushes an operator
toward committing it to make the tooling work.

`validate_document` rejects any legible aggregate-term key outright. An
artifact with a readable term name does not load.

## The demonstration pack

`demo.v1.json` lets the system run end to end without the production policy. It
is not a starting point to tune, and the difference matters: an artifact with a
believable spread of numbers is indistinguishable at a glance from a fitted one,
and whoever copies it into production ships values nobody measured.

So the pack contains exactly two kinds of number, marked per key by `basis`:

| `basis` | Meaning |
|---|---|
| `derived` | Has a stated, checkable source. A production pack would likely carry it unchanged. |
| `placeholder_midpoint` | The arithmetic midpoint of the key's declared valid range, chosen by nothing. |

Weights are uniform for the same reason — none was fitted, and equal weights
say that more plainly than any spread could.

Three things keep it honest:

- `tests/test_demo_policy_pack.py` asserts weights are uniform and every
  placeholder sits exactly on its midpoint. Tuning the demo pack fails the suite.
- `validate_document` rejects a `placeholder_midpoint` entry in a pack marked
  `production`, so the pack cannot be relabelled and shipped.
- `Policy.banner()` reports how many thresholds are placeholders, on every run.

Regenerate:

```bash
python tools/make_demo_policy.py
```

The generator's `DERIVED` table is the readable record of which numbers have a
source and what that source is. Nothing enters it without an answer to *who
says so*.
